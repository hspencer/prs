The PICTOS proyect
Visual and Procedural Supports for
Cognitive Accessibility of Public Services

The PICTOS project allowed us to work for two years conducting inclusive research to identify the most pressing needs of adults with intellectual disabilities. They told us that their quality of life is strongly affected by a lack of autonomy due to the low accessibility of public services, with particular emphasis on health, transportation, administrative procedures, and leisure.
Together with the team, we designed a system of visual and procedural supports to enable everyone to access the value provided by these services, that is, to successfully complete transactions. With the team, we designed a visual grammar for constructing pictograms, a plain language approach for writing instructions, and an architecture to define publishing software for supports across different services.

I have continued developing multiple pictograms, such as those created for older adults with dementia and other cognitive impairments for use at home, providing functional support for daily living activities. Through this process, I realised the need to systematise the construction of a visual phrase using reusable iconic elements. This led me to the following definition of a pictogram: A pictogram is a graphical representation that transcends written language by conveying a concept or action through a combination of iconic elements arranged meaningfully. It acts as a visual phrase, integrating several elements into a coherent, context-sensitive whole. A pictogram establishes a memorable physical association with its referent and serves as a clear, iconic abstraction within a structured visual language system.

Text as Image
Here is the thing: SVG is both an image format and a text-based code format. This means that you can edit it as text, and the image will change accordingly. Note that the code holds verosimilitude to the semantic structure of the image. This opens a more granular way to edit and adapt pictograms, and for the system to learn from those edits.

PictoNet Generative Pipeline

From text input to adaptive pictogram output

But LLMs are, by definition, black boxes. They are complicated, obfuscated, and not designed to be transparent nor cognitively accesible for humans. But, what if we can deconstruct the design process behind a pictogram, and use that as a pipeline to guide the LLM in generating pictograms? This is one line of my initial enquiry, were I'm interviewing pictogram designers.
From one end we input text (voice or written), which is then processed through Natural Language Processing to extract semantic features. These features are then mapped to visual elements using a predefined set of design rules and principles. Finally, the visual elements are composed into a coherent pictogram that effectively communicates the intended message.
The system is designed to be adaptive, allowing for customization based on user preferences and context. This includes adjusting the level of detail, color schemes, and cultural considerations to ensure the pictograms are both effective and inclusive.
The goal of this generative pipeline is to create a flexible and scalable system that can produce high-quality pictograms on demand, enhancing communication for individuals with complex communication needs.
